# 模拟绘画过程视频

从一张静态输入图推导轮廓，制作可观看的模拟过程：先描线，再显色，最后呈现完整原图。必须明确称为“模拟绘画过程”，不能冒充真实录屏、真实笔触历史或原作者的作画记录。

## 默认成片要求

- 先以连续移动的铅笔笔尖描出结构。断开的轮廓间抬笔移动，不应画出连接两个无关物体的长线。
- 主体先上色，背景保持白纸或线稿；随后完成背景。显色阶段不出现笔、手或机械手臂。
- 输出 H.264 编码的 MP4，yuv420p，启用 faststart。原始宽高比保持不变，不为 16:9 裁图或加黑边。
- 用户要求 4K 60fps 时，本技能默认解释为长边 3840、60fps，并明确报告实际宽高。例如 3:4 输入为 2880×3840。不要把它表述为横版 UHD 3840×2160。
- 小图放大不增加真实细节。必须同时记录原图尺寸、工作渲染尺寸与实际输出尺寸；不将放大输出宣称为原生 4K 细节。

## 选择输入和遮罩

配套脚本最适合完整、居中、浅色背景的单主体图片。自动前景使用 GrabCut；主体与背景复杂交织或主体贴边时，应提供与输入同尺寸、白前景黑背景的遮罩，并先检查遮罩。人物或群像不能依赖一个中心矩形就宣称语义分割正确。

先看输入图，确定哪些部分是主体、哪些是背景，查看自动或用户提供的遮罩，再制作正式视频。无法可靠分离时，说明问题并请用户提供遮罩或允许人工调整；不要默默把背景当主体上色。

## 执行

依赖见 [requirements.txt](requirements.txt)，另需 PATH 中可用的 FFmpeg 与 FFprobe。保持源图不变，输出到新的文件名。示例命令：

```text
python scripts/render_process.py --input source.png --out output/process.mp4 --long-edge 3840 --fps 60 --duration 16
```

复杂主体增加 `--foreground-mask mask.png`。先做短预览可以降低 `--long-edge` 和 `--fps`，但正式交付仍需按用户要求渲染并验证，不能用预览参数替代。

脚本的描线是图像轮廓推导，颜色阶段是由外轮廓向内部展开的显色模拟，不能称为真实手工分区涂色。需要真实矢量笔画或逐对象的颜色顺序时，应使用用户提供的分层画稿或另行制作路径。

## 验收与交付

读取 FFprobe 的实际 codec、像素格式、宽高、帧率、帧数和时长；不能仅凭扩展名确认 MP4 或 H.264。检查至少描线、主体显色、最终三个时刻，确认笔尖只出现在描线阶段、主体先完成、末帧接近输入图且没有比例变形。

交付正式 MP4、便于观看的预览、参数 JSON 和原图/视频阶段对比样张。对比样张原图放上方，视频关键帧放下方；网页应能播放视频，README 应链接到实际视频文件。视频不自动加字幕；要加时按当前用户要求使用西班牙语。

样例记录见 [references/sample-validation.md](references/sample-validation.md)。上传账户需遵循用户明确的发布指令。


## 发布样张要求

每个对外展示的样品都必须直接包含原图与对应成品。默认原图在上、成品在下；横向更合适时允许左原图、右成品。用完整文件排版，不重画原图，不拉伸或裁切主体。仓库首页也要显示这些对比，不能只放成品。引用类型要标清：风格参考不冒充同一主体的原照。
